================================================================================
SYSTEM ARCHITECTURE: AUTOMATED EDUCATIONAL PHRASE EXTRACTION PIPELINE
================================================================================
Target Scope: Processing raw PDF/CSV research data into clean, unified, 
              and ranked multi-word educational tokens for VOSviewer ingestion.
Environment: Local Laptop Deployment (CPU-optimized, Zero Training Required).
================================================================================

--------------------------------------------------------------------------------
BLOCK 1: TEXT EXTRACTION & STANDARDIZATION
--------------------------------------------------------------------------------
* PURPOSE:
  Reads unstructured input documents from disk, extracts raw text strings, 
  and performs initial regex-based data sanitization.
* INPUT:
  Raw research PDF files and unparsed CSV tables.
* OUTPUT:
  A clean Python list of raw text strings partitioned by document or page.
* METHOD:
  Iterates through local directories using a loop. It employs 'pdfplumber' 
  or 'PyPDF2' for extracting text layout, and applies 're.sub' regex functions 
  to clean corrupted characters, remove extra whitespaces, and unify Hebrew 
  punctuation layouts (e.g., standardizing double quotes in abbreviations).

--------------------------------------------------------------------------------
BLOCK 2: MORPHOLOGICAL ANALYSIS
--------------------------------------------------------------------------------
* PURPOSE:
  Deconstructs the complex Hebrew prefix-suffix grammar by isolating structural 
  particles and resolving every word to its core dictionary base form.
* INPUT:
  Clean Python list of raw text strings from Block 1.
* OUTPUT:
  A stream of tokenized word objects, where every word is separated from its 
  attached prepositions and mapped directly to its Lemmatized form (Lemma).
* METHOD:
  Streams the standardized text into a local spaCy pipeline. It utilizes the 
  pre-trained Hebrew model 'he_core_news_sm' to analyze the underlying Hebrew 
  morphology, strip away attached clitic prepositions and conjunctions 
  (such as מ, ש, ה, ו, כ, ל, ב), and compute the true linguistic base form.
  (Example: The token "ובבתי" is morphologically split into "ו" + "ב" + "בית").

--------------------------------------------------------------------------------
BLOCK 3: POS TAGGING & TEMPLATE FILTERING
--------------------------------------------------------------------------------
* PURPOSE:
  Classifies parts of speech and applies syntactic pattern rules to capture 
  meaningful multi-word domain-specific candidates while discarding structural noise.
* INPUT:
  Stream of tokenized and lemmatized word objects from Block 2.
* OUTPUT:
  Filtered pairs of adjacent tokens (Bigrams) that strictly fulfill predefined 
  grammatical criteria.
* METHOD:
  Utilizes the pre-trained 'token.pos_' property generated by the spaCy model 
  or the 'avichr/hebrew-bert-pos' Hugging Face transformer pipeline running on CPU. 
  It executes a sliding-window array scan over adjacent words ($i$ and $i+1$). 
  It passes the token pair through a strict conditional filter if it matches:
  - Pattern A: [NOUN / PROPN] + [ADJ] (e.g., אוריינות דיגיטלית, חוסן נפשי)
  - Pattern B: [NOUN / PROPN] + [NOUN / PROPN] (e.g., צוותי חינוך, בתי ספר)
  All generic elements (verbs, prepositions like "על ידי") are completely dropped.

--------------------------------------------------------------------------------
BLOCK 4: TOKEN JOINING & NORMALIZATION
--------------------------------------------------------------------------------
* PURPOSE:
  Glues validated word combinations into a single compound machine-readable token 
  and eliminates structural grammatical variations to avoid network node splitting.
* INPUT:
  Filtered pairs of valid matching compound tokens from Block 3.
* OUTPUT:
  An optimized array of unified, underscore-separated text strings.
* METHOD:
  Extracts the underlying Lemmas of the validated word pairs and joins them 
  using string f-expressions (f"{Lemma1}_{Lemma2}"). It runs basic Python 
  string normalizations ('startswith', 'replace') to look for definite articles 
  (ה) at the front of the second word. If found, it clips the letter off to 
  ensure that variants like "אוריינות דיגיטלית" and "אוריינות הדיגיטלית" compress 
  into the exact same single node: 'אוריינות_דיגיטלית'.

--------------------------------------------------------------------------------
BLOCK 5: STATISTICAL WEIGHTING (TF-IDF)
--------------------------------------------------------------------------------
* PURPOSE:
  Evaluates the global contextual importance of all extracted compound terms, 
  ranking domain-specific pedagogical vocabulary above generic linguistic noise.
* INPUT:
  Array of unified, underscore-separated compound strings from Block 4.
* OUTPUT:
  A final ranked Dataframe of multi-word educational tokens sorted from highest 
  to lowest statistical significance score, ready for VOSviewer ingestion.
* METHOD:
  Instantiates scikit-learn's 'TfidfVectorizer' class and feeds it the processed 
  corpus via 'fit_transform()'. The mathematical formula calculates Term Frequency 
  (TF) against Inverse Document Frequency (IDF). It penalizes phrases that appear 
  randomly or evenly across all papers (e.g., 'המחקר_הנוכחי', 'שנה_שעברה'), while 
  maximizing the score of true educational terms that appear intensely inside 
  relevant thematic contexts.
